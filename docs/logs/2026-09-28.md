**Gate 5: the Coding Council is the default, with lean/full modes (`apps/agent-runtime`)**
- `COUNCIL_MODE=lean|full|auto` (default `auto`), from plan §7 "cheap improvements" #1:
  - `lean`: no Planner and no plan review. The Implementer plans as its first step and opens its
    summary with that plan, then checks → Reviewer → fix rounds run as before. The project is

  - `full`: unchanged (Planner → plan review → Implementer → checks → review → fix).

## Decisions

- **Gate 5 is council-only in practice.** The Mastra single agent stays only as a fallback a
  human must name. Remove it once lean mode has run on a few real Tasks. Lean ≈ the single agent
  plus an independent review, at a little more cost.
- **The mode is chosen by rules, not by a model,** and shown in the plan before approval, so the
  choice can be explained and audited.
- **The author is whoever approved, not whoever started the run.** The approver is responsible
  for the change.
- **AURA stays the committer on every server-side commit.** Git history still shows the commit
  was made by AURA, and the CLI can find checkpoints reliably.
- **The identity comes only from the server:** the API reads the approver's profile. The request
  body and the model are never trusted for it.
