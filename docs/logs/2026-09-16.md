## Decisions
- Moved `ARCHITECTURE.md` to `docs/ARCHITECTURE.md` to match the documented layout.
- No shared monorepo tooling for now — each app is installed/run on its own (`cd apps/<app> && npm install && npm run dev`). Revisit `packages/`/workspace tooling once there's duplication worth factoring out.
- Axiata brand colours are the platform's UI palette, defined once in `apps/web/src/index.css` under `@theme` — Red is now the primary (no blue), with Gold/Orange/Red-Orange/Purple/Magenta as accents, per brand direction.
- Accounts are admin-provisioned only, no public signup — matches the platform's human-gate-first philosophy even at the account level.
- `ask_user` belongs to the Orchestrator only, never to a delegated sub-agent (PO/BA). A documented bug in the sibling `minibuilder-mastra` reference project showed a suspended `ask_user` call inside a delegated sub-agent has no path back to a human; PO/BA are mode-based (draft/revise/file, driven by the Orchestrator's own approvals) instead.
- Agents call the Jira MCP server directly from `apps/agent-runtime` for now, not through a policy-checked Tool Gateway (`docs/ARCHITECTURE.md §7` describes one, but it lives in `apps/api`, which doesn't exist for this yet). Acceptable short-term since a human still approves every Jira write inside the Orchestrator; revisit once the gateway is built.
