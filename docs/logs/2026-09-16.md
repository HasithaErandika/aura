# 2026-09-16

## Done
- Designed the overall system architecture for AURA (governed AI agent platform for the SDLC): layered service view, authorization model, human-in-the-loop workflow, agent layer/contract, tool gateway, testing architecture, data architecture, reliability/cost controls, observability, deployment architecture, and phased delivery plan — captured in [../ARCHITECTURE.md](../ARCHITECTURE.md).
- Wrote the SRS (`docs/srs/`) derived from the architecture: overview, overall description, functional requirements, non-functional requirements, external interfaces, data requirements, and use cases mapped to the seven approval gates.
- Scaffolded the basic monorepo structure per [ARCHITECTURE.md §13](../ARCHITECTURE.md#13-monorepo-layout): `apps/{web,api,agent-runtime,sandbox-runner}`, `packages/{contracts,policy,db,agents,tools,workflows,evals,ui,telemetry}`, `tests/{e2e,api,integration}`, `infra/{terraform,docker,ci}`, `docs/{adr,security,runbooks,workflows,srs,logs}`.
- Initialized the git repository.
- Removed `packages/`, `tests/`, and `infra/` for now — deferred until there's real cross-app code to share; Mastra owns agent/workflow structure inside `apps/agent-runtime` in the meantime.
- Dropped the root pnpm workspace/Turborepo setup (`package.json`, `pnpm-workspace.yaml`, `turbo.json`, `tsconfig.base.json`). Each app (`web`, `api`, `agent-runtime`) is now a fully standalone npm project with its own lockfile, installed and run independently.
- Initialized `apps/api` (Express + TypeScript): health check, stubbed `POST /runs` and `POST /approvals/:id/decide` routes (Zod-validated, 501 for now), builds and runs clean.
- Initialized `apps/agent-runtime` via the official Mastra scaffold and `apps/web` via the official Vite scaffold.
- Rebuilt `apps/web` on top of that scaffold: React + Vite + TypeScript + Tailwind CSS v4, themed with Axiata's corporate colour palette as CSS theme tokens (`src/index.css`). Built a first dashboard UI — sidebar nav, topbar, stat cards, a 7-gate pipeline stepper, an approval inbox, and an agent registry panel — as the starting shell for the Agent Workspace / Approval Inbox / Run Console / Agent Registry / Audit Explorer screens.
- Removed `apps/sandbox-runner` — deferred, likely Mastra-managed later.
- Wired up Supabase in `apps/api`: service-role client, auth middleware that verifies the bearer token and loads the caller's role from a new `profiles` table, `GET /me`, and admin-only `GET/POST /users`, `PATCH /users/:id/role`, `DELETE /users/:id`. Added `supabase/schema.sql` (role enum, `profiles`, RLS) and a `bootstrap-admin` script to create the first account (no self-serve signup).
- Built out `apps/web` auth flow: Supabase client, `AuthProvider`/`useAuth`, `ProtectedRoute`/`AdminRoute`, and four routes — `/` landing, `/login`, `/dashboard`, `/admin` (user management: create/role-change/deprovision).
- Renamed the project to **AURA** (AI Unified Resource & Automation, by Dialog) across the architecture doc, SRS, and every app — root folder name intentionally left as-is, to be renamed manually later.

## Decisions
- Moved `ARCHITECTURE.md` to `docs/ARCHITECTURE.md` to match the documented layout.
- No shared monorepo tooling for now — each app is installed/run on its own (`cd apps/<app> && npm install && npm run dev`). Revisit `packages/`/workspace tooling once there's duplication worth factoring out.
- Axiata brand colours are the platform's UI palette, defined once in `apps/web/src/index.css` under `@theme` — Red is now the primary (no blue), with Gold/Orange/Red-Orange/Purple/Magenta as accents, per brand direction.
- Accounts are admin-provisioned only, no public signup — matches the platform's human-gate-first philosophy even at the account level.
