## Decisions
- The Orchestrator decides the workflow dynamically. Nothing in `apps/api` or `apps/web` encodes a step order; the API observes delegations, tool results, and pauses and records them. The only decisions made outside the model are who may run an agent and which role answers a pause, both plain data in `apps/api/src/modules/policy/policy.ts`. This replaces the "lookup table workflow" in the original architecture baseline (see the doc update).
- Agents propose structured drafts; code renders and files them. A draft crosses a model boundary at most twice per version. Sub-agents hold no tools, so untrusted Jira text cannot reach a write tool.
- Conversations, agent memory, and drafts stay in the runtime's own storage. Supabase holds identity, the governance record of runs, approvals with snapshots and decisions, and the audit trail, referencing runtime state by id.
- A pause raised before any delegation, or after delegating to an agent with no approver role, goes back to the person who started the run rather than to a role.
- `JIRA_PO_TOOLS` and `JIRA_BA_TOOLS` are gone; the runtime finds the get, create, and comment tools on the Jira MCP server by suffix.
- Mastra Studio stays available to engineers and is linked from the Agent Registry for admins.
- `reasoningFormat: 'hidden'` over `'parsed'` for the reasoning-leak fix: the ask was to not show thinking at all and to stop spending tokens on it, not to capture it for later inspection, so there's no separate reasoning trace to debug a bad draft from — only the final JSON/text.
- Revising an already-filed Story whose index no longer exists in the revised set (the human removed it) leaves that Story's Jira issue untouched rather than deleting it automatically; only matched indices get synced.
