# 2026-09-29

## Done

**Only the API can call the agent runtime (`apps/agent-runtime` + `apps/api`)**
- Found: the API already sent `MASTRA_RUNTIME_TOKEN` when set, but the runtime never checked it.
  Anyone who could reach port 4111 could run agents, resume a suspended gate or write workspace
  files, skipping policy, approvals and audit.
- New `server/runtime-auth.ts`: a server-wide Mastra middleware. When `MASTRA_RUNTIME_TOKEN` is
  set, every request needs `Authorization: Bearer <token>` (SHA-256 + `timingSafeEqual`),
  otherwise `401`. This covers Mastra's own `/api/*` routes and AURA's custom routes (`/workspace`,
  `/dev-workspace`, `/council`, `/runners`, …). CORS preflights pass.
- New `AURA_MODE=local|server` (default `local`) in both apps, from ADR-2's rollout note.
  `server` refuses to start without the token. The runtime also refuses a token shorter than 32
  characters. `local` allows no token, with a startup warning, so Mastra Studio keeps working
  (Studio can't send the token).
- Checked against a live runtime (`AURA_MODE=server`, port 4199): no token and a wrong token →
  `401` on `/api/agents`, `/workspace`, `/council/registry` and `PUT /workspace/:epic/file`; the
  right token → `200`. Server mode with no token logs the error and doesn't serve.

## Decisions

- **The token stays optional in local mode.** Requiring it would break Mastra Studio for every
  developer; loopback binding is the boundary there. `AURA_MODE=server` is where it's enforced.
- **One mode switch in both apps, not a per-feature flag.** Later server-only rules (no
  `SANDBOX_MODE=host`, no full terminal) hang off the same `AURA_MODE`.
