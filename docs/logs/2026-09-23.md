- New `workflows/tester-workflow.ts`: Gate 7 is now a bounded `.dountil()` loop (Mastra) - run

  source via a Playwright-reported spec-file match, current git commit, app output) and diagnose
  through an explicit hierarchy (infra → app startup → test/env → test implementation →
  application defect → requirements ambiguity) before acting. Only two outcomes act
  automatically: a test implementation problem routes back to QA (`reviseQaScenario` - only the
  one failing scenario, never the whole plan) or an application defect routes to the Coding Agent
  (`runCodingFix` - a scoped fix, no fresh scaffold). Any low-confidence or "unknown" diagnosis
  escalates straight to a human - the loop never guesses. Retries capped at 3 attempts, then sets
  `HALTED_LOOP_GUARD` (a DB status that existed since `0002_runs_approvals_audit.sql` but nothing
  had ever set until today) and is picked up by `run-stream.service.ts`.
- `qa-drafts.ts`: scenarios now carry `revision`/`revisionNote`. `qa.ts`: reads real
  scaffolded/implemented code (`workspace/read-scaffold-context.ts`) before writing scenarios,
  new `revise-scenario` mode + exported `reviseQaScenario()`.
- `code.ts`: prompt now also asks for unit/integration tests; extracted `runCodingProviderPrompt`

## Decisions
- Removed the human Tester role rather than keeping it alongside `qa_engineer` - it added no
  capability `qa_engineer` didn't already have, only a segregation-of-duties split the redesign
  no longer needs. Existing `tester` users auto-remap to `qa_engineer` in the migration.
- Kept Claude Code/Codex as host-CLI-login providers rather than trying to broker their personal
  OAuth login through the platform (not how those tools are designed to be used by a third
  party) - demoted, not removed. Real multi-user support for them should come from BYOK API keys
  later, a separate, legitimate integration path (not built yet).
- Deliberately did not build an Integration Agent, remote Git (GitHub App/PR), or multi-repo
  support in this pass - sequenced correctly *after* worktree-per-Task, not alongside it, per the
  explicit milestone scope agreed before starting.
- `copyScenariosIntoScaffold` (QA's best-effort dev convenience copy) stays pointed at the shared
  base scaffold, not per-Task worktrees - it was never what any gate actually reads from (Tester
  mounts the canonical QA workspace copy directly), so the ambiguity of "which Task's worktree"
  doesn't need solving for something that's already just a convenience.
- Logged (not silently fixed) two real model/execution reliability findings from the KAN-45
  transcript (Orchestrator dropping `mode` on a resumed tool call; Codex exiting 243 with no
  captured output) rather than guessing at a fix without being able to reproduce either.
