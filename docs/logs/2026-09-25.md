# 2026-09-25

## Done

**Plan** — [docs/plans/aura-code-cli-council.md](../plans/aura-code-cli-council.md): a developer
surface built around the terminal (the `aura` CLI plus a web terminal) instead of Docker/browser-only,
and a multi-agent Coding Council on free-tier models. The plan was later rewritten to match what was
actually built, with an efficiency and alternatives assessment (§7).

**Personal access tokens + git identity (`apps/api`)**
- Migration `0006_access_tokens_git_identity.sql`: `access_tokens` table (SHA-256 hash only,
  prefix, `kind` personal/terminal, expiry, revocation, last used), plus
  `profiles.git_name/git_email`. **Not applied to Supabase yet.**
- `middleware/auth.ts` resolves `aura_pat_…` bearers to their owner, then runs the same
  profile/role checks as a session. `req.user.via` = session|token; a token cannot mint tokens.
- `/me/tokens` (list/create/revoke, audited), `PUT /me/git-identity`; Profile → Access tokens card.

**`packages/aura-client` + `apps/cli` (`aura`)**
- Typed REST/SSE client shared by the CLI (and later the extension).
- Commands: `login/logout/whoami`, `tasks`, `open [--code|--path]`, `status`, `code`
  (drafts Gate 5 with every `delegate_to_code` argument spelled out, which works around the
  KAN-45 dropped-`mode` failure), `approve/reject/revise` (snapshot-hash pinned), `say`,
  `diff`, `commit`, `push [--pr]`.
- `commit` runs locally, so it's authored by the developer; it folds AURA checkpoint commits into
  one commit and adds `Co-authored-by`/`AURA-Task`/`AURA-Run` trailers, and never rewrites the
  developer's own commits.
- Verified end to end against a mock API and a real git worktree.

**Coding Council (`apps/agent-runtime`, Gate 5 provider `council`)**
- `workflows/coding-council.ts`: Planner (read-only tools, Markdown plan) → Reviewer (no tools,
  JSON verdict) → Implementer (write/edit/`run_check`) → checks → review of the real diff →
  bounded fix rounds. A failing check forces CHANGES. Checkpoint commit per round, token budget,
  transcript in `.aura/council/`. The Task is not moved to In Review unless the Reviewer approved.
- `lib/sandbox.ts`: typecheck/build/test/lint as fixed ids resolved from `package.json`, host
  (default, no Docker) or docker mode.
- Model chains per role live in `agents/registry.ts` (`COUNCIL_*_MODEL_IDS`). Loop limits come from
  `.env`. Moving to Claude means adding `anthropic/claude-sonnet-5` first in each list.
- The council has its own registry entry (`coding-council`, reported live via `GET /council/registry`),
  a policy row (Developer runs and approves, Architect/admin read) and its own provenance stamp.
- Streaming: `data-council-turn` → run step `source: council` → SSE `council`, rendered by the
  CLI, the web chat and the Run Console.
- One real run: plan → plan review (APPROVE) → build → `test` passed → checkpoint. The code
  review then failed on an **expired Groq key**. That exposed two bugs, now fixed but not re-run:
  turns were labelled with the first model in the chain rather than the one that answered, and
  the loop only retried on 429 instead of any provider error.

**Web**
- **Project Files** (the old Scaffolded Files) replaces the Design Documents page, which is deleted,
  with `/app/design-docs` redirecting to it. One VS Code-style view:
  - Explorer with the Epic's design documents (every pipeline role reads them; the Architect
    edits; PO/BA/Architect can Comment → Send to Architect; Markdown preview).
  - The Task's code (Developer, Architect, QA and admin see it; Developer edits).
  - The editor and panel are visible from the moment the page opens.
- Bottom panel with **Terminal** and **Runners** tabs:
  - Terminal: xterm.js ⇄ runtime WebSocket (:4112), opened with an API-signed, single-use
    ticket. A Python `pty` bridge gives a real shell, because `node-pty` failed to build here.
    Restricted mode is used off loopback. `aura` is auto-signed in through an 8h `terminal`-kind
    token, sent encrypted.
  - Runners: `GET /runners` live snapshot of Docker containers (CPU/memory/processes against
    `CONTAINER_LIMITS`), host capacity, council runs, host checks, and terminal sessions (other
    users shown as "another user").
- Council turns render as a live log in chat and in the Run Console timeline.

## Decisions

- The CLI comes first; the VS Code extension and Monaco are deferred. CodeMirror stays, with a
  terminal under it.
- The council starts on free-tier models, with Claude added later by editing the registry lists
  (env overrides were dropped so all model choices live in one place). The Reviewer uses a
  different model family from the Implementer on purpose.
- Only the Reviewer returns strict JSON, because its verdict is the only output that drives the
  loop. There's no `install` check, because worktree `node_modules` is shared through a symlink.
- The browser connects to the runtime's terminal WebSocket directly; the API signs and audits
  tickets rather than proxying the connection.
- The developer is the commit author; AURA is recorded in trailers.
- `coding-agent` stays as the Gate 5 step, with the council as one provider. Whether to remove
  the other three providers is still open.
